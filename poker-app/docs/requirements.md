| 項目 | 内容 |
| --- | --- |
| 版 | v0.1（ドラフト・レビュー待ち） |
| 作成日 | 2026-10-10 |
| 対象 | `poker-app/` |

## 1. 概要

友人同士が **リンクを共有するだけで** 1対1（ヘッズアップ）のノーリミットテキサスホールデムを対戦できる Web アプリ。
トーナメント形式で、時間経過に応じてブラインドが上昇する。初期スタック・ブラインド表・レベル時間などは対戦前に自由に設定できる。

## 2. 前提とスコープ

### 2.1 前提

- 利用者は作成者とその友人。一般公開・不特定多数のマッチングは想定しない。
- 同時に複数の部屋（数部屋〜数十部屋規模）が独立して遊べる。
- チップはゲーム内の仮想ポイントのみ。実際のお金・換金できる価値のやり取りは扱わない。
- ログイン不要。リンクを開いてニックネームを入れるだけで参加できる。
- 無料枠のホスティングで運用する。
- UI は日本語のみ。

### 2.2 スコープ内（MVP）

- 部屋の作成とリンク共有、2人での参加
- 対戦前の設定（初期スタック・ブラインド表・アンテ方式・レベル時間・持ち時間・タイムバンク）
- ヘッズアップ NLHE のゲーム進行一式
- 時間制のブラインド上昇（トーナメントクロック）
- 持ち時間とタイムバンク、時間切れの自動処理
- 一時停止・切断・再接続
- ハンド履歴、効果音、マック、リマッチ、投了

### 2.3 スコープ外（§19 に今後の候補として記載）

3人以上の対戦、観戦、アカウント・戦績、チャット、オールイン時の勝率表示、ラン・イット・トワイス、AI 対戦、英語 UI。

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| ホスト | 部屋を作成したプレイヤー。対戦設定を編集できる |
| ゲスト | リンクから参加したプレイヤー |
| ボタン（BTN） | ディーラーボタンを持つプレイヤー。ヘッズアップでは SB を兼ねる |
| レベル | ブラインド表の1段。SB / BB / アンテの組 |
| トーナメントクロック | レベルの経過時間を測る時計。一時停止中は止まる |
| 持ち時間 | 1回のアクションに使える時間 |
| タイムバンク | 持ち時間を超えたときに消費される、試合全体での予備時間 |
| マック | ショーダウンで手札を見せずに捨てること |

## 4. 利用の流れ

```
ホスト                                   ゲスト
──────                                   ──────
トップ画面「部屋を作る」
  └ ニックネーム入力
ロビー（設定を編集）
  └ リンクをコピー／共有 ───────────▶ リンクを開く
                                           └ ニックネーム入力
                                         ロビー（設定を閲覧）
                                           └「準備OK」
        ◀──── 3秒カウントダウン後に対戦開始 ────▶
対戦画面（ハンドを繰り返す）
        ◀──── どちらかのスタックが0で試合終了 ────▶
結果画面 ──「リマッチ」(両者押下) ──▶ ロビーへ戻る（同じ設定）
```

部屋の状態遷移：

```
LOBBY ──(ゲスト準備OK)──▶ STARTING(3秒) ──▶ PLAYING ⇄ PAUSED
  ▲                                            │
  └──────(両者がリマッチ)─────── FINISHED ◀────┘ (片方のスタック0 / 投了)
```

## 6. 対戦前の設定

### 6.1 設定項目

| 項目 | 範囲・形式 | 既定値 |
| --- | --- | --- |
| プリセット | ターボ／通常／ディープ | 通常 |
| 初期スタック | 100〜10,000,000（整数） | 10,000 |
| ブラインド表 | 1〜40レベル。各レベルに SB・BB・アンテ | §6.3 |
| アンテ方式 | なし／BBアンテ／各自アンテ | なし |
| レベル時間 | 1〜60分（1分刻み、全レベル共通） | 10分 |
| 持ち時間 | 10〜120秒（5秒刻み） | 30秒 |
| タイムバンク | 0〜300秒（10秒刻み） | 60秒 |

- 設定を編集できるのはホストのみ。ゲストには同じ内容が即時に反映された状態で表示される。
- ホストが設定を変更すると、ゲストの「準備OK」は解除される。
- ゲストが「準備OK」を押すと3秒のカウントダウン後に対戦が始まる。

### 6.2 ブラインド表の編集

- プリセットを選ぶと、初期スタック・レベル時間・ブラインド表がまとめて入力される。そのあと自由に編集できる。
- 行の追加・削除と各値の直接編集ができる。「プリセットに戻す」で元に戻せる。
- アンテ方式を切り替えると、アンテ列に標準値を自動で入れる（手動で上書き可）。
  - BBアンテ：BB と同額
  - 各自アンテ：BB の 1/10（1未満は1）
  - なし：アンテ列を非表示にして 0 として扱う
- 入力チェック
  - エラー（開始不可）：SB ≥ 1、BB ≥ SB、アンテ ≥ 0、整数のみ
  - 警告（開始は可能）：BB が前のレベルより小さい、初期スタックが Lv1 の BB の 10 倍未満

## 7. ゲームルール

### 7.1 基本

- 52枚のデッキ1組を使う。ハンドごとにシャッフルする。
- 各プレイヤーに2枚、ボードにフロップ3枚・ターン1枚・リバー1枚を配る。
- 7枚中のベスト5枚で役を比べる。役の強さは一般的なテキサスホールデムに従う。
- 役名の表示：ハイカード、ワンペア、ツーペア、スリーカード、ストレート、フラッシュ、フルハウス、フォーカード、ストレートフラッシュ、ロイヤルフラッシュ

### 7.2 ボタンとブラインド

- 最初のハンドのボタンはランダムに決める。以降は毎ハンド交代する。
- ヘッズアップのルールに従う。
  - ボタンが SB を払い、BB は相手が払う。
  - プリフロップはボタン（SB）から行動する。
  - フロップ以降は BB 側から行動する。
- アンテ
  - BBアンテ：BB のプレイヤーが、表のアンテ額を1回払う。
  - 各自アンテ：両者が表のアンテ額を払う。
  - アンテはデッドマネーとしてポットに入る。コール額には含めない。
- スタックが足りない場合は、ブラインドを先に払い、残りをアンテに充てる。払えた分だけでオールインになる。
- ハンド開始時点のレベルのブラインドを使う（§8）。

### 7.3 ベッティング

- 選べるアクション：フォールド、チェック、コール、ベット、レイズ、オールイン
- 金額は「合計でいくらにするか（to）」で扱う。
- 最小ベットは BB（スタックが BB 未満ならオールインのみ）。
- 最小レイズは、直前のベット／レイズの増分以上（最低 BB）。オールインは額に関係なく可能。
- 相手がオールインしている場合、選べるのはコールかフォールドのみ。
- プリフロップで SB がコールした場合、BB はチェックかレイズを選べる（BB のオプション）。
- コールされなかったベット額は、ハンド終了時に本人へ返す。

### 7.4 オールインとショーダウン

- これ以上アクションが起きない状態（オールインがコールされた等）になったら、両者の手札を即座に公開する。この場合はマックできない。
- 残りのボードは 1.5 秒間隔で1枚ずつ（フロップは3枚同時に）配る。
- 通常のショーダウン
  - 先に公開する人：リバーで最後にベット／レイズした人。リバーでベットがなければ BB 側（先に行動する側）。
  - 後から公開する人：勝ち・引き分けなら自動で公開する。負けなら自動でマックする。
- ハンド終了後の結果表示中は、手札を公開していないプレイヤーが「見せる」を押して任意に公開できる（フォールド勝ちの場合も含む）。

### 7.5 ポットの分配

- 勝者がポット全額を得る。
- 引き分けは等分する。割り切れない端数チップは BB 側（ボタンでない側）に渡す。
- 結果表示：勝者、獲得額、役名。勝ちの5枚を強調表示する。
- 次のハンドまでの表示時間：フォールドで決着なら 2 秒、ショーダウンなら 5 秒。そのあと自動で次のハンドを始める。

### 7.6 試合終了

- ハンド終了時にどちらかのスタックが 0 になったら試合終了。
- 投了：メニューから確認つきで選べる。投了した時点で相手の勝ちになる。

## 8. トーナメントクロック

- 試合開始と同時にスタートする。一時停止中（§10）は止まる。
- 現在のレベル ＝ `min(経過時間 ÷ レベル時間, 最終レベル)`
- レベルが上がるのは時間が来た瞬間だが、ブラインドへの反映は次のハンドから。
  - ハンドの途中でレベルが上がった場合は「次のハンドから Lv.N（SB/BB）」と通知する。
- 最終レベルに達したら、そのブラインドのまま続ける。
- 常に表示する情報：現在のレベル、SB/BB(/アンテ)、次のレベルまでの残り時間、次のレベルのブラインド、ハンド番号

## 9. 持ち時間とタイムバンク

- 手番になると持ち時間のカウントを始める。残り 10 秒で警告（表示と効果音）する。
- 持ち時間を使い切ると、自動でタイムバンクの消費が始まる。
- タイムバンクは試合全体で共通の残量で、補充はない。
- 持ち時間もタイムバンクも尽きたら、チェックできればチェック、できなければフォールドを自動で行う。
- 切断中のプレイヤーはタイムバンクを使わない（持ち時間だけで自動処理する）。

## 10. 一時停止・切断・再接続

### 10.1 一時停止

- どちらのプレイヤーでも、いつでも（ハンドの途中でも）一時停止できる。
- 一時停止中は、トーナメントクロックと持ち時間の両方が止まる。アクションは受け付けない。
- どちらのプレイヤーでも再開できる。再開時は3秒のカウントダウンをはさむ。
- 両者とも切断した場合は自動で一時停止する。再開は手動で行う。

### 10.2 切断と再接続

- 参加時にサーバーがプレイヤートークン（推測できないランダム値）を発行する。ブラウザの localStorage に部屋ごとに保存する。
- 同じ端末・ブラウザでリンクを開き直すと、自動でその席に戻る。
- 片方だけが切断している間も、クロックと進行は止まらない。切断中のプレイヤーの手番は §9 の時間切れ処理で進む。
- 相手が切断中であることを対戦画面に表示する。
- 通信が切れたら自動で再接続する（間隔を徐々に延ばしながら再試行）。復帰時は最新の状態を受け取る。
- 対戦中は画面のスリープを防ぐ（Screen Wake Lock API に対応したブラウザのみ）。

### 10.3 部屋の扱い

- 部屋 ID は推測困難なランダム文字列にする。URL の例：`/r/{roomId}`
- リンクを知っていれば誰でもゲスト席に入れる。2席が埋まったあとにアクセスすると「満席」と表示する。
- 最後の接続から 24 時間たった部屋のデータは削除する。

### 11.2 アクション操作

- 状況に応じて、フォールド／チェック／コール（額つき）／ベット／レイズ／オールインのボタンを出し分ける。
- 金額は、スライダー・数値入力・クイックボタンのどれでも指定できる。
  - プリフロップのクイックボタン：2.5BB、3BB、4BB、オールイン
  - フロップ以降のクイックボタン：1/3、1/2、2/3、ポット、オールイン
  - 範囲外の値は最小レイズ額〜オールイン額に自動で補正する。
- 自分の手番でないときは操作を無効にする。
- 手番が来たら、表示と効果音で知らせる。

### 11.3 メニュー

一時停止／再開、ハンド履歴、効果音のオン・オフ、投了

## 12. ハンド履歴

- その試合の全ハンドを、新しい順に一覧表示する。
- 各ハンドの詳細
  - ハンド番号、レベル、ブラインド、ボタン、開始時のスタック
  - 自分の手札
  - 相手の手札（公開されたときのみ）
  - 各ストリートのアクションと金額、ボード、結果（勝者・獲得額・役名）
- 直前のハンドは、ワンタップで開けるようにする。

## 13. 効果音

- 鳴らす場面：カード配布、チェック、ベット／コール（チップ音）、フォールド、自分の手番、持ち時間の警告、レベルアップ、ポット獲得
- オン・オフは端末ごとに保存する（localStorage）。既定はオン。

## 14. 試合終了とリマッチ

- 結果画面に、勝者、プレイしたハンド数、試合時間、到達レベルを表示する。
- 両者が「リマッチ」を押すと、同じ設定が入った状態でロビーへ戻る。
  - ホストは設定を変えられる。
  - ゲストが「準備OK」を押すと開始する。

## 15. 公平性とセキュリティ

- ゲームの状態とルールの判定はすべてサーバーが持つ。クライアントは表示と入力だけを担当する。
- シャッフルは暗号論的乱数（`crypto.getRandomValues`）と、偏りのない Fisher–Yates 法で行う。
- 相手の手札・デッキの残り・未公開のボードはクライアントに送らない。
  - 状態はプレイヤーごとに必要な情報だけに絞ってから送る。
  - ハンド履歴も同じ扱いにする。
- アクションはサーバーで検証する（手番・金額・最小レイズ・スタック上限）。不正な入力は拒否する。
- 個人情報は保持しない。保存するのはニックネームだけ。

## 16. 非機能要件

| 区分 | 要件 |
| --- | --- |
| 応答性 | アクションが相手の画面に反映されるまで、通常 0.5 秒以内 |
| 規模 | 同時に数部屋〜数十部屋（個人利用の規模） |
| 対応ブラウザ | 最新の Chrome / Edge / Firefox / Safari、iOS Safari 16 以上、Android Chrome |
| 画面 | 幅 360px 以上。スマホ縦画面を優先し、PC でも崩れない |
| 費用 | Cloudflare の無料プランの範囲内 |
| 時刻同期 | 残り時間はサーバーの締め切り時刻から計算する。端末の時計のずれはサーバー時刻で補正する |
| 可用性 | SLA なし。サーバー再起動後も部屋の状態は保存から復元する |

## 17. 技術方針

| 層 | 採用技術 |
| --- | --- |
| 言語 | TypeScript |
| フロントエンド | React + Vite |
| サーバー | Cloudflare Workers + Durable Objects（1部屋 = 1 Durable Object） |
| 通信 | WebSocket（Hibernation API）、JSON メッセージ |
| タイマー | Durable Object Alarm（持ち時間切れ・部屋の期限切れ） |
| 永続化 | Durable Object ストレージ（部屋の状態・ハンド履歴） |
| 配信 | Workers の静的アセット配信（フロントとサーバーを1回でデプロイ） |
| テスト | Vitest（エンジン・サーバー）、Playwright（2つのブラウザで E2E） |

```
ブラウザ(ホスト) ─┐                    ┌──────────────────────────┐
                  ├─ WebSocket ───────▶│ Worker（ルーティング）    │
ブラウザ(ゲスト) ─┘                    │  └ Durable Object: 部屋  │
                                       │     ├ ゲームエンジン      │
                                       │     ├ クロック／Alarm     │
                                       │     └ ストレージ          │
                                       └──────────────────────────┘
```

- ゲームエンジンは、通信や UI から独立した純粋な TypeScript モジュールにする。入力（状態とアクション）から次の状態を決定的に計算する。
  - 単体テストしやすい。
  - 将来 AI と対戦させる場合も流用しやすい。
- サーバーは状態が変わるたびに、各プレイヤー向けに絞り込んだ状態をまとめて送る。演出用のイベント（配布・ベット・勝敗など）も一緒に送る。
- ローカル開発は `wrangler dev` で動かし、ブラウザを2つ開いて対戦を確認する。

## 18. テスト方針と受け入れ基準

### 18.1 テスト方針

- エンジンの単体テスト
  - 役判定（全役、キッカー、ホイールストレート、引き分け）
  - ベッティングの規則（最小レイズ、BB のオプション、ショートオールイン）
  - ブラインド・アンテ不足時の処理
  - 返却されるベット、端数チップ
- サーバーの結合テスト：2クライアントでの部屋作成〜試合終了、切断と再接続、一時停止、時間切れ
- E2E：Playwright で2つのブラウザコンテキストを使い、1試合を最後まで通す

### 18.2 受け入れ基準

- [ ] リンクを共有するだけで、2人が別々の端末から同じ部屋に入って対戦できる
- [ ] ホストが変えた設定（初期スタック・ブラインド表・アンテ方式・レベル時間・持ち時間・タイムバンク）が、ゲストの画面と実際の対戦に反映される
- [ ] レベル時間がたつと、次のハンドから表のブラインドに上がる
- [ ] ヘッズアップのボタンとブラインド、行動順が §7 のとおり
- [ ] 相手の未公開カードが、通信内容のどこにも含まれない
- [ ] 時間切れで、チェックまたはフォールドが自動で行われる
- [ ] 一時停止中は、クロックと持ち時間の両方が止まる
- [ ] リロードしても、同じ席・同じ状態で再開できる
- [ ] ハンド履歴で過去のハンドを確認でき、相手の未公開の手札は表示されない
- [ ] どちらかのスタックが 0 になると結果画面に移り、リマッチできる
- [ ] スマホの縦画面（幅 360px）で、横スクロールなしで操作できる

## 20. 確認事項（回答以外で仮に決めた点）

ヒアリングの回答を超えて仮に決めた点です。違和感があれば指摘してください。

1. **プリセットの値**（§6.3）：3種とも同じブラインド表で、初期スタックとレベル時間だけを変えている。
2. **最終レベル以降**：最終レベルのブラインドのまま続ける。
3. **両者とも切断したら自動で一時停止**する（誰もいない部屋で試合が勝手に進まないようにするため）。
4. **切断中はタイムバンクを使わない**（不在の相手を長く待たなくて済むようにするため）。
5. **マックの扱い**：後から公開する人が負けていれば自動でマックし、あとから任意で「見せる」ことができる。
6. **投了機能**を追加した。
7. **部屋の保存期間**：最後の接続から 24 時間。
8. **4色デッキ**を採用した。
9. **デプロイには Cloudflare アカウント（無料）が必要**。実装中はローカル（`wrangler dev`）で動作確認する。
